# Babylon × Blender: how the project balances them

Snapshot of current state, 2026-10-25. Describes what is, not what must be.

## Principle
Babylon owns runtime, data and evaluation. Blender owns UX: names, layout, icons, shortcuts, interaction. Where they conflict, Babylon's model wins and the Blender UX is mapped onto it.

## Decisions in place
| Area | Babylon side | Blender side | Current choice |
|---|---|---|---|
| Source of truth | Scene built by user code | .blend file | Code. Interactive edits are a diff over code ("Remember scene edits"), similar to Blender library overrides |
| Identity | Object names | Datablock names / pointers | `metadata.wbId`, falling back to name; `workbench.editable(node, {id})` for explicit ids. Renaming in code drops saved edits |
| Axes | Y-up, left-handed | Z-up | Babylon axes everywhere (gizmo, grid, views); Blender colours |
| Viewport shading | Scene `clearColor` | Theme background in Solid | Solid/Wireframe use the theme background; Rendered shows the scene as authored |
| 3D Viewports | One canvas per engine; `engine.registerView` renders a scene into extra canvases | Any number of 3D Viewport areas, each with its own view, shading, overlays and camera view | `src/viewport/views.js` renders every 3D Viewport as an engine view of one hidden working canvas. Its size follows an anchor (the view showing the compositor, else the largest view) and changes only with the layout; other views render into its top-left corner through `camera.viewport`, so there are no per-frame resizes. Per-view state is applied in `onBeforeViewRenderObservable`: shading, overlays, the world background and volume, and the compositor, all as cheap switches. Render effects attach per camera to rendered views. The compositor's frame graph ignores camera viewports, so one rendered view at a time (the last clicked) shows it. Views stop rendering when idle: no input, playback, user render observers or loops, animations, particles, video or loading. Editing is shared: one selection and gizmo set; picking, projection and modal transforms use the view under the pointer. Split a 3D Viewport (area menu or corner drag) to add one |
| Video Sequencer | None | Video Sequencer editor (Sequencer, Preview, sidebar), File Browser | KubeezCut fork (`Propolisa/KubeezCut`, branch `bylonder`) built as a library (`npm run build:embed`) and published to its `embed-dist` branch, pinned in `package.json` as `kubeezcut-embed`. `src/sequencer/sequencer-kubeezcut.js` is the only module that imports it (lazily). Islands are React roots in dock areas; the embed stylesheet is scoped under `.kc-embed` with cascade layers flattened and `src/sequencer/theme.css` maps its tokens to Bylonder's theme and Blender's strip colors. AI features are compiled out of the embed. The edit is the scene's `sequenceEditor` document slice (`src/sequencer/sequence-editor.js`), so undo goes through Bylonder's history and Remember Scene Edits, versions and render snapshots carry it; KubeezCut's playhead follows the scene frame. Scene strips (Add > Scene) show any scene of the project through its camera: frames render in a render context per scene, cached by a content hash of the scene, prefetched, at the Proxy Render Size; Strip > Rebuild Proxy stores them in OPFS. Media stays in KubeezCut's per-project media library. Strip properties are not yet Bylonder channels |

| Animation | `Animation` evaluates curves | Actions, slots, F-Curves, NLA, drivers | One action per project (`name`, `tracks`); tracks keyed by `[id, path]`; Bézier/Linear/Constant; evaluation writes live objects (no evaluated copy) |
| Scene time | `Animation` fps; no scene clock | Scene: frame_current/start/end/step, fps, preview range, auto keying | `src/scene/time.js`, shaped like Blender's Scene time fields, owns the playback clock; the action evaluates at its frame. Saved with the action in the always-saved animation payload (v2; v1 migrates), not with scene edits. Frame step skips frames during playback. `loop` is ours (Blender always loops) |
| Document / undo | None | ID database, memfile undo | Named document slices (`capture`/`apply`) plus object snapshots; undo stores whole-state snapshots, 100 steps |

| Geometry nodes | `NodeGeometry` | Geometry Nodes modifier | Modifier type in our stack; group stored as JSON on the modifier |
| Particles | Node particle sets | Particle systems on objects | Stored on objects; Properties > Particles |
| Logic | FlowGraph, no editor package | (none current) | Own minimal editor; isolated in `src/graphs/logic*.js` |
| Scene settings | `Scene` properties (`gravity`, `activeCamera`) | Scene datablock: camera, unit_settings, gravity | Document slice `scene`, shaped like Blender's Scene; Babylon writes isolated in `src/scene/scene-babylon.js`; saved as a diff from code |

| World in viewport | Always rendered | Solid shows theme background, no world volume | Background, skybox and fog only in Rendered shading and camera view; environment lighting stays on in all modes |
| Properties tabs | (none) | Render, Output, View Layer, Scene, World, Collection, Object, ... | Blender order; header shows the Blender breadcrumb (Scene > World) |

| Render vs compositor | One post-process stack per camera; frame graph replaces it | EEVEE settings vs compositor nodes | Render tab holds engine settings and color management; bloom and other post effects belong to the Compositor, as in Blender 4.2+. | Output | No file rendering; `VideoRecorder` records the live canvas in real time | Format (resolution, %), Frame Range, Output (file format), Encoding (container, codec, quality, keyframe interval) | Fields on the `render` slice shaped like `scene.render`, `image_settings` and `ffmpeg`. Containers MPEG-4, QuickTime, Matroska, WebM; codecs H.264, H.265, AV1, VP9, VP8 as each container allows. Audio comes from the Video Sequencer's mix (AAC, or Opus in WebM) |
| Offline render | Realtime render loop | Render Image (F12), Render Animation (Ctrl F12), View Render (F11), Render Result window | `src/render/`: each job runs in a hidden render context (`render.html`) built by `src/runtime/world.js` from a snapshot of the document, the same code the viewport uses. | Graph inputs | Input blocks, `editableInPropertyPage` | Exposed group inputs | Reflected into channels by block name; Node Material: uniform inputs only (avoids shader rebuilds) |

## Scene-level data pattern
Each Blender struct is a plain JSON record named like its Blender counterpart (camelCase), held by one document slice with `capture`/`apply` (a diff from the code-built scene) and edited only through the slice's methods. Each slice has one `*-babylon.js` adapter that is the only code writing the matching Babylon state. Panels read the record and call slice methods; they never touch Babylon. Animatable fields register channels with paths relative to their datablock (`scene` + `viewSettings.exposure`, `world:<id>` + `volume.end`). Persistence: scene time and the action are saved always; the other slices are scene edits, saved when Remember Scene Edits is on.

## Deferred / open
- Scene: Keying Sets, Audio, Rigid Body World, Simulation range, Background Scene.
- Render: Depth of Field (belongs with Camera data), Film (filter, transparent), Gamma, curves, white balance. Output: audio, metadata stamps, file path, saving straight to disk (results download today).
- Collections: holdout, indirect only, disable in renders, instancing, collection colors; lights and cameras stay in the Scene Collection; duplicates go to the active collection rather than the source's collections.
- World: Mist Pass, Light Probe and Sun settings, Viewport Display color, world node trees.
- Action slots, NLA, layers, drivers as data, F-Curve modifiers, editable handles.
- Object data (transforms, modifiers, particles) as a document slice instead of `storage.js` snapshots.
- Undo storing diffs instead of all channel values.
- Config UI for FlowGraph blocks that need one; pointer-event blocks absent in Babylon 8.32.
- Replace the Logic editor if Babylon ships one.
- Babylon editors are singletons; their internal undo is separate from ours.
