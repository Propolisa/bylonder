# Babylon × Blender: how the project balances them

Snapshot of current state, 2026-10-25. Describes what is, not what must be.

## Principle
Babylon owns runtime, data and evaluation. Blender owns UX: names, layout, icons, shortcuts, interaction. Where they conflict, Babylon's model wins and the Blender UX is mapped onto it.

## Decisions in place
| Area | Babylon side | Blender side | Current choice |
|---|---|---|---|
| Source of truth | Scene built by user code | .blend file | Code. Interactive edits are a diff over code ("Remember scene edits"), similar to Blender library overrides |
| Identity | Object names | Datablock names / pointers | `metadata.wbId`, falling back to name; `workbench.editable(node, {id})` for explicit ids. Renaming in code drops saved edits |
| Axes | Y-up, left-handed | Z-up, right-handed | Blender's (x, y, z) is Babylon's (x, z, y) (`src/makesrna/rna-bylonder.js`, `src/draw/draw-view.js`). Everything the UI shows is in Blender's axes: the navigation gizmo (Z up, Blender's theme colors and negative axis balls), the floor grid on Blender's XY plane with X and Y axis lines, overlay shapes |
| Viewport shading | Scene lights and materials, `clearColor` | Workbench in Solid and Wireframe, the engine in Material Preview and Rendered | `src/draw/workbench.js` ports Workbench: Solid lights each object with the "Default" studio light in view space (Blender's shader math, including its fast reciprocal) in its material's base color (Blender's default surface, 0.8 grey, without one), ignoring the scene's lights. With X-ray, Solid draws every surface at the X-ray alpha (0.5) with Blender's weighted blended order-independent transparency (`workbench_transparent_accum_frag.glsl`): surfaces accumulate into two targets before the view renders and a resolve draws them over the background; revealage is summed as -log(1 - alpha) under Babylon's additive blend instead of Blender's multiplicative one, and the resolve blends in display color, so see-through surfaces are slightly lighter than Blender's. Wireframe draws each object's face edges, unlit, in the theme's wire, selected and active colors, through everything (X-ray). Each view's camera has its own Babylon render pass, so a Solid or Wireframe view gives meshes a Workbench material for that pass only (`setMaterialForRenderPass`); Rendered views and offline renders keep the scene's materials. Solid and Wireframe use the theme background |
| Viewport overlays | None (`renderOutline` extrudes along normals in object space) | Overlay engine: grid, extras for cameras, lights, empties, selection outlines | `src/draw/overlay-grid.js` ports Blender 5.2's line grid (three levels chosen by the distance to the floor, fading with distance, angle and level, axis lines in the theme's blended axis colors) in one alpha-blended pass instead of four depth-biased ones; lines are clipped to the view volume in the vertex shader, as long lines through the eye plane do not rasterize reliably. `src/draw/overlay-extra.js` and `overlay-shape.js` port the extras' shapes (`overlay_shape.cc`) and `overlay_extra_vert.glsl`: cameras (frame and triangle, filled for the scene camera), lights by type (Babylon point, spot, directional and hemispheric as sun, rect area as area), with their icon and line to the floor, and empties by `metadata.empty_display_type` and `empty_display_size`. Light settings Babylon lacks use Blender's defaults (spot blend 0.15, clip start 0.05, cutoff 40); a point light's radius is Babylon's `radius`. Empties select by their shapes; cameras and lights are not selectable objects yet. `src/draw/overlay-outline.js` ports the selection outline (`overlay_outline.hh`) and the anti-aliasing pass that draws its lines: a prepass of the outlined meshes' ids and depth, the detect pass and the line anti-aliasing in screen space, so the outline is Blender's width in pixels at any scale and distance, in the Active Object and Object Selected colors (the transform color while moving). As Blender, only selected objects are outlined: a selected parent (an empty or a group) outlines nothing of its children. Blender tests the outline's depth against the scene's in the shader; here the last pass writes it as the fragment depth and draws twice, under `LEQUAL` and, dimmed, under `GREATER`. Blender blends overlays in linear color, Babylon in display color, so partly covered pixels are a little darker. With X-ray the prepass draws silhouette edges, from an adjacency line list built per mesh (`mesh_batch_cache_edge_detection`), placed and instanced as its mesh; bones and morph targets do not move it |
| Startup view | The project's camera | startup.blend's 3D View | Every 3D Viewport starts at Blender's startup view (its view rotation, distance 18.39 and location) with Blender's viewport lens (50 mm on a 36 mm sensor at zoom 2, fitted to the longer side), whatever the project's camera |
| 3D Viewports | One canvas per engine; `engine.registerView` renders a scene into extra canvases | Any number of 3D Viewport areas, each with its own view, shading, overlays and camera view | `src/editors/space_view3d/views.js` renders every 3D Viewport as an engine view of one hidden working canvas. Its size follows an anchor (the view showing the compositor, else the largest view) and changes only with the layout; other views render into its top-left corner through `camera.viewport`, so there are no per-frame resizes. Per-view state is applied in `onBeforeViewRenderObservable`: shading, overlays, the world background and volume, and the compositor, all as cheap switches. Render effects attach per camera to rendered views. The compositor's frame graph ignores camera viewports, so one rendered view at a time (the last clicked) shows it. Views stop rendering when idle: no input, playback, user render observers or loops, animations, particles, video or loading. Editing is shared: one selection and gizmo set; picking, projection and modal transforms use the view under the pointer. Split a 3D Viewport (area menu or corner drag) to add one |
| Video Sequencer | None | Video Sequencer editor (Sequencer, Preview, sidebar), File Browser | KubeezCut fork (`Propolisa/KubeezCut`, branch `bylonder`) built as a library (`npm run build:embed`) and published to its `embed-dist` branch, pinned in `package.json` as `kubeezcut-embed`. `src/sequencer/sequencer-kubeezcut.js` is the only module that imports it (lazily). Islands are React roots in dock areas; the embed stylesheet is scoped under `.kc-embed` with cascade layers flattened and `src/editors/space_sequencer/theme.css` maps its tokens to Bylonder's theme and Blender's strip colors. AI features are compiled out of the embed. The edit is the scene's `sequenceEditor` document slice (`src/sequencer/sequence-editor.js`), so undo goes through Bylonder's history and Remember Scene Edits, versions and render snapshots carry it; KubeezCut's playhead follows the scene frame. Scene strips (Add > Scene) show any scene of the project through its camera: frames render in a render context per scene, cached by a content hash of the scene, prefetched, at the Proxy Render Size; Strip > Rebuild Proxy stores them in OPFS. Media stays in KubeezCut's per-project media library. Strip properties are not yet Bylonder channels |
| Editable values | Object properties | RNA paths | Channel registry: `[id, path]` with `get`/`set`, components in the path (`position.x`); re-registering replaces the binding |
| Animation | `Animation` evaluates curves | Actions, slots, F-Curves, NLA, drivers | One action per project (`name`, `tracks`); tracks keyed by `[id, path]`; Bézier/Linear/Constant; evaluation writes live objects (no evaluated copy) |
| Scene time | `Animation` fps; no scene clock | Scene: frame_current/start/end/step, fps, preview range, auto keying | `src/blenkernel/scene/time.js`, shaped like Blender's Scene time fields, owns the playback clock; the action evaluates at its frame. Saved with the action in the always-saved animation payload (v2; v1 migrates), not with scene edits. Frame step skips frames during playback. `loop` is ours (Blender always loops) |
| Document / undo | None | ID database, memfile undo | Named document slices (`capture`/`apply`) plus object snapshots; undo stores whole-state snapshots, 100 steps |
| Materials | Standard, PBR, Node materials | Material datablocks, slots | Blender datablock UX over Babylon types; slots via `MultiMaterial`; Principled = `PBRMaterial`; Surface type converts in place |
| Users / orphans | None | User count, fake user, orphans dropped on save | Counted from slots on demand; saved edits drop zero-user created materials unless fake user; undo keeps them |
| Node editors | NME, NGE, NRGE, NPE (React) | One Node Editor with tree types | Babylon editors embedded unchanged, Blender skin via generated CSS-module map; context follows Blender (active material, modifier, scene, emitter) |
| Compositor | Frame graph (alpha) | Compositor, viewport compositor, backdrop | `NodeRenderGraph` behind Use Nodes; shown in the Compositor's backdrop (an engine view through the scene camera behind the nodes) and in one Rendered or camera-view 3D Viewport |
| Geometry nodes | `NodeGeometry` | Geometry Nodes modifier | Modifier type in our stack; group stored as JSON on the modifier |
| Particles | Node particle sets | Particle systems on objects | Stored on objects; Properties > Particles |
| Logic | FlowGraph, no editor package | (none current) | Own minimal editor; isolated in `src/nodes/logic.js` and `src/editors/space_node/logic-editor.js` |
| Scene settings | `Scene` properties (`gravity`, `activeCamera`) | Scene datablock: camera, unit_settings, gravity | Document slice `scene`, shaped like Blender's Scene; Babylon writes isolated in `src/blenkernel/scene/scene-babylon.js`; saved as a diff from code |
| Units | Unitless | Scene > Units, display only | 1 Babylon unit = 1 m before Unit Scale; one shared `unitSettings` read by every property row; unitless input uses the displayed unit |
| World | No World object: `clearColor`, `environmentTexture`, skybox, fog | World datablock linked to the scene; Background and Volume shaders | Document slice `worlds`, shaped like Blender's World (`background`, `volume`, `visibility`); `src/blenkernel/scene/world-babylon.js` is the only code that maps it onto the scene. Code-built scene becomes "World", saved as a diff. Colors stored in Babylon's space (no linear conversion). Volume Scatter = exponential fog; extra Babylon fog modes listed as such |
| World in viewport | Always rendered | Solid shows theme background, no world volume | Background, skybox and fog only in Rendered shading and camera view; environment lighting stays on in all modes |
| Properties tabs | (none) | Render, Output, View Layer, Scene, World, Collection, Object, ... | Blender order; header shows the Blender breadcrumb (Scene > World) |
| Render settings | `ImageProcessingConfiguration`, `DefaultRenderingPipeline`, SSR, SSAO2, motion blur | scene.render, scene.eevee, view_settings, display_settings | Document slice `render` shaped like those structs; `src/blenkernel/scene/render-babylon.js` is the only writer of tone mapping/exposure/contrast and render-engine effects. Samples = MSAA; Raytracing Screen-Trace = SSR; Fast GI (Ambient Occlusion) = SSAO2; Motion Blur shutter = motion strength; Exposure in stops (`2^stops`); Looks = image processing contrast. Effects attach to the camera of each view in Rendered shading or camera view and read the geometry buffer renderer, not the scene-wide prepass, so each 3D Viewport renders them on its own; Fast GI uses a fixed sample pattern, so Render Image matches the rendered viewport. View transforms: Standard, Khronos PBR Neutral, ACES and Babylon Standard (AgX, Filmic, False Color absent) |
| Render vs compositor | One post-process stack per camera; frame graph replaces it | EEVEE settings vs compositor nodes | Render tab holds engine settings and color management; bloom and other post effects belong to the Compositor, as in Blender 4.2+. With Compositing Use Nodes on, Babylon's frame graph bypasses Render tab effects (Color Management still applies) |
| Output | No file rendering; `VideoRecorder` records the live canvas in real time | Format (resolution, %), Frame Range, Output (file format), Encoding (container, codec, quality, keyframe interval) | Fields on the `render` slice shaped like `scene.render`, `image_settings` and `ffmpeg`. Images via canvas encoding, video via WebCodecs muxed by mediabunny (MPL-2.0, unmodified dependency). Containers MPEG-4, QuickTime, Matroska, WebM; codecs H.264, H.265, AV1, VP9, VP8 as each container allows. Audio comes from the Video Sequencer's mix (AAC, or Opus in WebM) |
| Offline render | Realtime render loop | Render Image (F12), Render Animation (Ctrl F12), View Render (F11), Render Result window | `src/render/`: each job runs in a hidden render context (`render.html`) built by `src/runtime/world.js` from a snapshot of the document, the same code the viewport uses. A virtual clock replaces `performance.now`, `Date.now`, `requestAnimationFrame` and `Math.random`; each sample is bracketed by `engine.beginFrame()`/`endFrame()` so `getDeltaTime()` follows it. Frames pre-roll from Frame Start. Render Samples average jittered renders (anti-aliasing) and, with Motion Blur, sub-frame times across the shutter (limited to one frame). Same project, same machine: identical pixels. With Post Processing > Sequencer on and strips in the edit, KubeezCut composites each frame (scene strips render at full quality in their render contexts) and the same host encoder writes video and audio |
| Collections | None; per-mesh `isVisible` | Collections (nested, objects in many), Scene Collection, view layers with exclude/hide per collection | Document slice `collections` shaped like Blender (`collections`, `scene`, `viewLayers`); objects linked nowhere count as Scene Collection members. `src/blenkernel/scene/collections-babylon.js` sets `isVisible` on meshes hidden through collections (per object, no inheritance, authored value restored). Selectability via one pick predicate. Layer collections keyed by collection id. New objects go to the active collection. Excluded or hidden objects are deselected |
| Grouping | Parent `TransformNode` | Parenting; collections | Collections replace groups in the UI. The old group command is "Parent to New Empty"; Ctrl+G creates a collection inside the active collection and moves the selection into it (Blender leaves it unlinked). M, Shift+M, Ctrl+Alt+G as in Blender |
| Viewport rendered gate | Always rendered | Solid uses workbench, Rendered uses the engine | One hub (`world.setViewportRendered`) switches world background/volume, render effects and the compositor together |
| Graph inputs | Input blocks, `editableInPropertyPage` | Exposed group inputs | Reflected into channels by block name; Node Material: uniform inputs only (avoids shader rebuilds) |

## Scene-level data pattern
Each Blender struct is a plain JSON record named like its Blender counterpart (camelCase), held by one document slice with `capture`/`apply` (a diff from the code-built scene) and edited only through the slice's methods. Each slice has one `*-babylon.js` adapter that is the only code writing the matching Babylon state. Panels read the record and call slice methods; they never touch Babylon. Animatable fields register channels with paths relative to their datablock (`scene` + `viewSettings.exposure`, `world:<id>` + `volume.end`). Persistence: scene time and the action are saved always; the other slices are scene edits, saved when Remember Scene Edits is on.

## Deferred / open
- Scene: Keying Sets, Audio, Rigid Body World, Simulation range, Background Scene.
- Render: Depth of Field (belongs with Camera data), Film (filter, transparent), Gamma, curves, white balance. Output: audio, metadata stamps, file path, saving straight to disk (results download today).
- Collections: holdout, indirect only, disable in renders, instancing, collection colors; lights and cameras stay in the Scene Collection; duplicates go to the active collection rather than the source's collections.
- World: Mist Pass, Light Probe and Sun settings, Viewport Display color, world node trees.
- Action slots, NLA, layers, drivers as data, F-Curve modifiers, editable handles.
- Object data (transforms, modifiers, particles) as a document slice instead of `editors/undo/storage.js` snapshots.
- Undo storing diffs instead of all channel values.
- Config UI for FlowGraph blocks that need one; pointer-event blocks absent in Babylon 8.32.
- Replace the Logic editor if Babylon ships one.
- Babylon editors are singletons; their internal undo is separate from ours.
